# System-Integration-Case-Study

> TradingView → Webhook → Make → Capital.com 的事件驅動自動化下單系統。
> 完整介紹：https://system-integration-case-study.vercel.app/

## 專案簡介

這是一套讓交易訊號從產生到下單全程自動化的系統：
TradingView 的策略訊號透過 Webhook 傳給 Make，經過條件判斷與資料驗證後，
呼叫 Capital.com API 自動執行下單，中間不需要任何人工介入。

**這個專案最大的價值不在交易本身，而在系統整合與工程方法。**
（策略績效不是重點，甚至可以說與交易策略無關）

## 核心功能

- **事件驅動架構**：以 Webhook 串接跨平台，訊號到下單全自動
- **JSON 契約設計**：固定欄位格式（action / epic / size / type），
  兩端嚴格對齊避免歧義
- **風控機制**：ATR 動態停損停利、分批平倉（TP1/TP2）、
  非交易時段強制平倉、連續虧損暫停
- **資料驗證與冪等**：Make 端做欄位驗證、白名單過濾、
  重複訊息去重，防止誤觸發與重複下單
- **多時間框架**：15 分判方向、1 分找進場，且使用已確認資料避免重繪

## 開發方法（本專案的重點）

我在這個專案裡建立了一套工程方法，而不只是把功能做出來：

- **雙 AI 協作流程**：一個 AI 負責實作、另一個負責審查，
  中間用固定格式的交接文件溝通
- **驗證不自驗**：功能完成後由獨立的乾淨上下文重新驗證，
  而非讓產出者檢查自己
- **版本控管**：以 Git 管理每一版策略的演進與回溯
- **回測三段隔離**：訓練期調參、驗證期檢驗、樣本外測試，
  防止過度擬合
- **失敗紀錄制度**：每個策略假設有編號，失敗就記錄死因，
  累積對問題的真實理解，而非直接重寫
